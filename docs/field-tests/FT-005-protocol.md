# FT-005 — مقارنة مظللي الأرض في HELIOS Web 3.4.0
البناء 13. حالة: بروتوكول، لا نتائج ميدانية. [تحقيق LAB](../investigations/LAB-window-shader-investigation.md).

المسار المرجعي يستخدم fragment shader 3.3 كما هو. المحسّن يستخدم برنامج WebGL مستقلًا، مع فروع uniform متجانسة لتفادي noise الإجرائي عندما تتوفر خريطة النهار أو السحب، وتفادي قراءة خريطة الليل عند غيابها. الخرائط الجزئية والبديل الإجرائي محفوظان. إذا تعذر بناء البرنامج المحسّن يستمر المرجعي وتتعطل خانة الاختيار. لا تغيير للدقة أو الإضاءة أو هندسة الأرض أو الزجاج أو Bloom. لا ادعاء أن برنامج التشغيل سيتجنب الحسابات بالفعل قبل القياس.

الإعدادات ← مظلل الأرض: محسّن (افتراضي) أو مرجعي. مستقل عن مسار الرسم. JSON schema v1: earth_shader، earth_maps لكل سياق أداء/محاكاة، earth_shader_optimized_available، earth_mesh_draws وearth_mesh_triangles، earth_maps في environment مع load_ms وupload_cpu_ms (زمن CPU، ليس زمن GPU أو الشبكة وحدها). تغيّر المسار أو جاهزية الخرائط يجعل النافذة مختلطة. لا رفع تلقائي.

## تجربة هاتف مصغرة
1. تحقق من COMMAND · 13، اختر Cinema وOptimized لمسار الرسم، تأكد من الخرائط 3/3. ابدأ سجلًا جديدًا.
2. ادخل المختبر واقترب من النافذة وانظر إلى الأرض؛ أوقف الحركة من قائمة المشهد وثبّت الكاميرا دون تحريكها. اختر مظلل الأرض المرجعي، أغلق القائمة، انتظر 25 ثانية (أول 5 إحماء). ثم المحسّن 25 ثانية. كرر المحسّن ثم المرجعي دون تغيير الموضع والدقة.
3. أدر النظر بعيدًا عن الأرض وثبت الكاميرا مجددًا. كرر المقارنة نفسها. دوّن الملاحظات البصرية والحرارة/انقطاعات الشبكة إن وجدت.
4. أوقف التسجيل، صدّر JSON. لا حاجة لإعادة التجول أو الالتحام الكامل. تحليل النوافذ المستقرة بحسب الدقة والقائمة وحالة الخرائط وزاوية الكاميرا من عينات المحاكاة. لا تقارن عينات مختلفة الدقة مباشرة.

اختبار Chromium يقارن بكسلات مشهد الأرض الثابت (متوسط الفرق المطلق لكل قناة ≤1 من 255، ونسبة البكسلات التي تتجاوز 8 في قناة ≤1%) ويتحقق من التصدير وتبديل المسار. هذه حدود اختبار في سياق محدد وليست إثبات تكافؤ على كل الأجهزة. لا حد FPS في CI. قياس GPU timer query، وعزل الزجاج وBloom، واختبار الخرائط المفقودة في المتصفح خطوات مستقلة لاحقة؛ لا نتائج مدعاة. Android 2.0 ثابت.
